# VisualFiles 功能设计与 UI 交互评审

评审日期：2026-11-05。评审基线：v0.7.12，Git 提交 `16bc303`。面向产品负责人、设计师及实现者。

VisualFiles 的产品定位清晰：让用户在 Codex 内找到本机项目文件、理解内容与改动，再把需要的上下文加入对话草稿。下一轮应优先提升搜索定位的可靠性、版本与引用范围的可见性，以及窄面板中的阅读效率。这些直接影响核心任务能否完成。

本次记录 11 项问题：4 项 P1、6 项 P2、1 项 P3。其中，搜索过滤空白、Markdown 搜索不定位、Markdown 对比缺少差异标记、窄面板内容遮挡及文档锚点失效已通过隔离浏览器复核。其余为源码支持的交互风险或需要用户验证的设计判断。

## 1 评审范围与判断依据

阅读了 `PLAN.md`、`README.md`、既有 `docs/REVIEW.md`，以及项目选择、搜索、树导航、内容与 Diff、文件操作、引用草稿和状态恢复的相关实现。本评审单独记录当前产品体验；旧评审中的实施记录继续保留，不把已经完成的功能再次列为待办。

证据分为三类：

- **渲染复核**：直接运行当前 React 组件，以隔离数据替换宿主通信；文件写操作被禁止。覆盖 1280×720 浅色、800×720 深色及 420×720 窄窗口。
- **源码确认**：沿实际调用路径确认行为或状态分支；未执行的场景明确标注。
- **设计判断**：基于任务流程提出的可用性判断，需要真实用户验证，不能当作已测得的用户行为。

真实 Codex 面板打开工具返回了工作目录绑定成功，但当前自动化环境没有可读取的面板标签，且限制读取 Codex 原生界面。因此，浏览器复核不代表真实宿主的安装、剪贴板、原生查看或引用草稿验收通过。未进行真实文件移动、删除、跨聊天发消息或用户访谈。

优先级定义：P1 阻碍核心任务或使结果难以正确理解，应进入最近一轮修复；P2 增加误解、试错或恢复成本，应在随后一轮收敛；P3 属于低成本一致性优化。此处不是安全审计或无障碍合规结论。

## 2 产品定位与功能取舍

### 2.1 核心用户与任务

主要用户是正在使用 Codex 理解和修改本机项目的开发者。非开发角色也可能阅读 Markdown、图片或产品文档，但当前 Git、HEAD、定义跳转及文件操作的表达更适合有项目经验的用户。

| 用户任务 | 目前能力 | 产品判断 |
| --- | --- | --- |
| 找到要讨论的文件 | 项目选择、文件树、文件名与全文搜索、过滤 | 覆盖完整，搜索结果及过滤状态需要更可信 |
| 理解文件和本地改动 | 只读代码、Markdown、图片、HEAD 与磁盘对比 | 范围合理，Markdown 与窄屏对比存在明显体验缺口 |
| 追踪代码含义 | JS/TS 定义跳转、跳转历史 | 有实际价值，能力范围应继续清楚表达 |
| 把上下文交给 Codex | 文件、目录、选中代码加入当前或新对话草稿 | 是核心差异化能力，入口和引用范围需要更突出 |
| 整理项目文件 | 新建、重命名、移动、复制、剪切、废纸篓删除 | 属于辅助任务，重点是操作可预期与结果可确认 |

建议用以下顺序安排信息与操作：**找文件 → 阅读或审阅 → 添加引用**。文件管理作为辅助能力保留在菜单中。

### 2.2 值得保留的设计

- 已登记项目和实际工作目录的边界明确，支持项目源目录与受管理 worktree；不提供任意目录回退。
- 内容只读、文件管理经显式菜单执行，删除进入废纸篓；底部已有说明。
- 默认单文件浏览，已有文件改动自动对比 HEAD 与磁盘；新增文件直接显示全文，规则容易建立预期。
- 引用进入未发送草稿；当前与新对话可选，保留用户检查和发送的控制权。
- 按工作目录保存布局与阅读位置，支持树键盘导航、分栏调整及持续错误反馈。
- 版本与构建标识、中文文件内查找、GFM 预览和 JS/TS 跨文件定义跳转已存在，应作为当前基础能力维护。

暂不建议扩展编辑保存、Git 暂存提交、任意目录浏览、完整 IDE 标签系统或更多语言解析。先修复核心流程中的确定性问题，再根据使用记录评估新增能力。

### R01 搜索过滤后的结果不可信

**场景与现状**：搜索得到一个未改动文件，再勾选“仅改动”，结果区变为空白，没有“没有匹配结果”。渲染复核已确认。空态判断使用原始 `results.length`，列表渲染才应用改动过滤。

另一个边界来自源码：服务先截取前 500 项，前端随后过滤。若符合改动条件的命中出现在截断范围之外，用户可能漏看结果；本次没有构造 500 项以上的大目录执行复现。

**影响**：用户无法区分“没有符合条件的文件”“仍在读取”和“结果未完整返回”，也不能信任改动搜索的覆盖范围。

**最小建议**：统一搜索范围、结果、数量、空态与截断的口径；“仅改动”应在截断之前参与筛选。空态写明当前条件，并提供“取消仅改动”。无搜索词且项目没有改动时，树区域也应显示明确空态。

**验收**：未改动文件命中后开启过滤，有清楚空态与解除入口；超过 500 项时不会因先截断而漏掉范围内的改动命中；加载、失败、无结果和已截断四种状态可以区分。

证据：[TreeSidebar.tsx](../src/ui/TreeSidebar.tsx#L162)、[useWorkspace.ts](../src/ui/useWorkspace.ts)、[workspace-search.ts](../src/workspace-search.ts)。

### R02 Markdown 搜索只能打开文件，不能到达命中位置

**场景与现状**：点击 Markdown 文首之外的全文搜索结果，文件仍按默认规则显示预览。隔离样例中点击带行号的命中后，两侧预览 `scrollTop` 均为 0。行号传给了 `CodeView`，预览没有消费定位信息。

**影响**：全文搜索的关键收益丢失。用户还要再次寻找匹配内容，长文档中尤为明显。

**最小建议**：从全文搜索进入 Markdown 时，以源码模式定位并高亮命中；普通树点击仍默认预览。搜索针对当前磁盘内容，自动 Diff 时也应优先定位磁盘侧，避免把相同行号误当成 HEAD 的对应位置。

**验收**：长 Markdown、普通代码文件及有 Diff 的文件，点击结果后均能直接看到当前磁盘的目标行；普通树打开 Markdown 保持默认预览。来源切换不丢失已有阅读状态。

证据：[ContentViewer.tsx](../src/ui/ContentViewer.tsx#L184)、[FilePreview.tsx](../src/ui/FilePreview.tsx)、[CodeView.tsx](../src/ui/CodeView.tsx)。

### R03 Markdown 的 Diff 状态与可见结果不一致

**场景与现状**：有改动的 Markdown 默认显示左右两份渲染结果，标题标为“Diff · HEAD”和“Diff · 磁盘”，正文没有增删标记。要看到代码差异，需要把两侧分别切到源码；只切一侧仍不会进入统一的文字 Diff。

**影响**：用户需要肉眼逐段比较，容易遗漏文档中细微但重要的改动。两个“Diff”标签暗示了更强的差异识别能力。

**最小建议**：已有改动的 Markdown 默认进入源码差异，使用一个共享模式入口；若保留双预览，将其明确命名为“预览对照”。无需为此新建 Markdown 语义 Diff 引擎。

**验收**：打开有改动的 Markdown 后无需额外操作即可识别文字增删；预览对照与源码差异名称清楚；不会形成难以理解的左右不同模式。

这是对 `PLAN.md` 中 Markdown 默认预览规则的有意调整，实施时应明确限定“有 Diff 时”的例外并同步文档。

证据：[ContentViewer.tsx](../src/ui/ContentViewer.tsx#L49)。

### R04 窄面板缺少适合阅读的布局

**场景与现状**：420px 宽度下，文件树与内容组至少占 561px，磁盘侧移出初始可视区，需横向滚动；隐藏文件树后，左右各约 210px，文件名和工具栏仍被明显压缩。800px 且显示文件树时，两侧文件名也只剩很短的片段。

**影响**：用户很难同时确认文件身份、版本、引用入口和代码内容。既有最小宽度与横向滚动符合当前 `PLAN.md`，这里评审的是这一产品约定的使用成本。

**建议**：以内容区实际宽度决定对比表示。建议把每侧 320px 作为初始设计参考：内容区不足 640px 时，用“HEAD／当前磁盘”版本切换展示活动版本；空间足够再并排。文件树可临时收起，主要阅读操作保持可达。

这会改变现有布局约定，需要同步 `PLAN.md`；640px 是待验证的设计阈值。尺寸变化应保留活动版本和阅读位置，不覆盖用户保存的树宽或对比偏好。从 HEAD 定义跳转进入时仍须展示 HEAD。

**验收**：420、800、1280px 下均能确认完整文件身份、切换版本、添加引用和关闭文件；关键操作无需横向寻找；窗口变化不误切内容版本、不丢失选区。

证据：[WorkspacePanel.tsx](../src/ui/WorkspacePanel.tsx#L156)、[ContentViewer.tsx](../src/ui/ContentViewer.tsx#L70)。

### R05 引用内容与目的地在操作前不够明确

**场景与现状**：标题栏以对话图标进入菜单，选项始终是“添加到当前对话／创建新对话”。实现会根据选区与版本决定发送文件路径、选中代码或 HEAD 文本，但菜单不会提前展示这些差异。宿主草稿能力缺失也在点击后才报错。

**影响判断**：新用户需要试操作才能发现核心价值；连续切换 HEAD、磁盘和选区时，可能对实际引用范围形成错误预期。本次未发送真实引用，未测得误操作率。

**最小建议**：提供可见文字入口“添加引用”，菜单中直接写明“引用文件”“引用选中代码 Lx–Ly”或“引用 HEAD 内容”，标注目标对话且说明“不自动发送”。“创建新对话”改为“添加到新对话草稿”。已知宿主不支持时，提前解释并提供复制路径。

不必新增强制确认弹窗；优先让现有菜单本身可检查。引用草稿与原生文件附件继续保持准确表述。

**验收**：未选代码、选中代码、HEAD 全文、HEAD 选区及不支持草稿接口五种状态下，操作前即可判断引用范围和目标；发送结果只进入草稿。

证据：[ContentViewer.tsx](../src/ui/ContentViewer.tsx#L158)、[useFileActions.ts](../src/ui/useFileActions.ts#L170)、[conversation.ts](../src/conversation.ts)。

### R06 错误恢复动作未与失败任务对应

**场景与现状**：连接失效有专门的“重新连接项目”，这是合理设计。其他错误，包括文件操作、剪贴板和引用失败，汇入全局错误条后统一提供“重试同步”；文件操作弹窗也复用同一错误值。

**影响**：刷新文件树无法解决剪贴板权限或草稿能力缺失。弹窗可能显示与当前动作无关的旧错误，使用户难以判断下一步。

**最小建议**：按错误来源提供恢复说明：读取失败重试读取，写入失败保留输入并允许用户再次提交，能力不支持提供更新或复制路径。打开新操作时清理无关错误，操作弹窗只展示相关失败。保留连接失效后暂停轮询、不自动重试写操作的规则。

**验收**：分别触发读取失败、重名冲突、剪贴板不可用及宿主不支持引用；提示与恢复动作逐一对应，用户输入保留，写操作不会后台重放。

证据：[WorkspacePanel.tsx](../src/ui/WorkspacePanel.tsx#L120)、[useWorkspace.ts](../src/ui/useWorkspace.ts)、[FileOperationDialog.tsx](../src/ui/FileOperationDialog.tsx)。本项未注入真实宿主故障执行验收。

### R07 文件移动缺少目标与过程反馈

**场景与现状**：树内拖拽落下后直接执行移动，目录和根区域有 drop 处理，但未见目标目录高亮、目标路径说明或成功提示。“移动到”弹窗读取目标时清空目录列表，没有单独的加载、空目录和读取失败视图；候选目录只排除了已删除项。

**影响判断**：用户难以提前确认移动落点；空列表可能被误认为无子目录。源目录及其后代等无效候选可能需要提交后才获得错误。本项只读检查，未执行真实拖拽或文件移动。

**最小建议**：先补目标高亮、有效落点反馈、移动结果提示及弹窗三种状态，过滤明确无效目标。保留后端防覆盖、禁止移入自身子目录等校验。若后续观察到误拖，再评估撤销，不为所有移动增加确认框。

**验收**：落到目录、根空白区和无效目标时反馈不同；慢请求、空目录和读取失败清楚可辨；冲突后源与目标均保持原状；成功后可定位新位置。

证据：[TreeNodes.tsx](../src/ui/TreeNodes.tsx)、[useFileActions.ts](../src/ui/useFileActions.ts#L273)、[FileOperationDialog.tsx](../src/ui/FileOperationDialog.tsx)。

### R08 项目切换与聊天归属的关系不清楚

**场景与现状**：按钮及对话框均称“打开项目”，首段说明突出“实验性项目接口”。实际选择只改变 VisualFiles 浏览目录，不改变聊天所属项目或工作目录；界面没有同等明确地解释这一点。

**影响判断**：跨项目查看并添加引用时，用户可能误以为聊天也已切换。技术接口说明对正常选项目没有直接帮助。

**最小建议**：面板内按钮用“切换浏览项目”，说明“仅切换文件树，不改变当前聊天所属项目”。正常说明聚焦操作；兼容性细节放在失败时的帮助信息中。保留已登记项目限制、路径区分和可重试入口。

**验收**：同名项目及多源目录能够区分；用户能说明“浏览项目”与“引用目标聊天”的关系；列表为空和客户端不支持时均有可执行的下一步。

证据：[Root.tsx](../src/ui/Root.tsx)、[WorkspacePanel.tsx](../src/ui/WorkspacePanel.tsx#L68)、[PLAN.md](../PLAN.md#打开方式与验收边界)。

### R09 Markdown 目录锚点不能到达章节

**场景与现状**：点击 `[安装方法](#安装方法)` 无滚动。渲染复核中标题没有 `id`，点击处理却调用 `document.getElementById`。相对文件链接携带的章节片段也会在路径处理时被去除。

**影响**：长 README 和使用文档失去目录导航能力，用户只能手动滚动。

**最小建议**：为标题生成稳定且可处理重复标题的锚点，在当前预览范围内解析；同文件及跨文件章节链接保留定位意图。左右预览应使用各自的定位范围，避免跳到另一版本。

**验收**：中文、空格、编码片段和重复标题能正确定位；双栏分别滚动对应侧；跨文件章节链接到达目标文件的章节；不存在的锚点有可理解反馈。

证据：[FilePreview.tsx](../src/ui/FilePreview.tsx#L98)、[file-utils.ts](../src/ui/file-utils.ts)。跨文件部分为源码确认，未进行浏览器复核。

### R10 视觉层级分散了核心任务注意力

**场景与现状**：项目名在顶栏及树头重复；同文件 Diff 两侧重复文件名、复制、引用和关闭操作；底部同时出现树状态、内容状态及全局说明。多数控制使用相近的 12px 灰色文字，主要引用入口仍是图标。深色代码区与外层面板还有明显底色切换。

**影响判断**：视觉风格总体克制，但任务主次不够明确。有限空间被重复控制占用，引用能力与版本状态需要用户主动寻找。没有进行视线追踪或对比度测量。

**最小建议**：同一文件保留一个共享身份栏与关闭动作，版本标签放在各侧；复制放次级菜单，引用保留可见文字。路径、同步、Git 和版本信息按层级收拢。默认保留简短“只读／菜单管理文件”提示，构建标识详情仍可查看。

建议继续复用现有 shadcn Base Nova 与 Tailwind tokens，校准编辑器背景、分隔线和文字层次；无需更换组件库或增加装饰色。

**验收**：单看静态界面即可指出当前文件、活动版本和添加引用入口；同文件只需一个明确关闭动作；浅深主题、长路径及焦点状态可读。Git 状态增加文字解释，不只依赖颜色和字母。

证据：[WorkspacePanel.tsx](../src/ui/WorkspacePanel.tsx)、[ContentViewer.tsx](../src/ui/ContentViewer.tsx)、[chrome.tsx](../src/ui/chrome.tsx)、[globals.css](../src/ui/globals.css)。

### R11 前进与后退的命名应体现历史范围

**场景与现状**：代码栏的按钮名称为“后退／前进”，历史只由定义跳转建立，普通点击文件树没有进入该历史。这符合当前产品约定。

**影响判断**：用户按常见浏览器或编辑器经验，可能期待它返回上一个打开的文件。

**最小建议**：将提示改为“返回上一处定义跳转位置／前往下一处定义跳转位置”，并在首次使用帮助中说明。普通浏览历史和最近文件先记录需求，暂不扩展。

**验收**：普通文件切换与定义跳转两种场景中，按钮状态和名称能解释为何可用或不可用；版本校验与过期目标拒绝继续保留。

证据：[CodeView.tsx](../src/ui/CodeView.tsx)、[useCodeNavigation.ts](../src/ui/useCodeNavigation.ts)。

## 5 建议的界面与状态规则

以下是下一轮设计方向，不是已经实施的界面。

| 区域 | 建议的信息与操作顺序 | 需要保持的约束 |
| --- | --- | --- |
| 项目栏 | 浏览项目与目录 → 分支／worktree → 刷新 | 切换浏览目录不改变聊天归属 |
| 文件树 | 搜索 → 文件名／全文 → 有效过滤条件 → 结果／树 | 大小写规则可见；无结果时能解除过滤 |
| 文件身份栏 | 文件名和可辨识路径 → 当前模式 → 添加引用 → 更多 → 关闭 | 同文件 Diff 共用身份，引用范围清楚 |
| 阅读区 | 普通全文、源码差异、预览对照；空间不足时切换版本 | HEAD 与磁盘边界不变，活动版本可见 |
| 状态区 | 与当前任务相关的状态、同步失败和恢复入口 | 常规轮询安静反馈，错误持续可恢复 |

需要统一的文案与语义：

- “HEAD（当前提交）”与“当前磁盘（含已暂存和未暂存改动）”在首次帮助或提示中解释；无需增加暂存区操作。
- 文件名与全文搜索都说明区分大小写；“搜索忽略文件”可改为更易理解的“包含 Git 忽略文件”，说明它只改变搜索范围，树中忽略项仍展示。
- “正在读取”“没有子目录”“没有符合筛选条件的结果”“读取失败”分别表达，避免用空白承担多种含义。
- “已复制文件，选择目标目录后粘贴”与“已复制路径”区分；文件内部剪贴板不暗示可以粘贴到系统应用。
- 操作按钮使用具体动词，如“新建文件”“移动到此目录”“移到废纸篓”；保留废纸篓恢复说明。
- 只读边界、键盘可达、清晰焦点及加载反馈继续作为基础要求。不能以文字或布局精简为由移除这些反馈。
