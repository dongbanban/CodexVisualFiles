# VisualFiles 实施规范

## 开始修改前

- 先读本次涉及的实现、调用方和 `PLAN.md` 中的产品约定；区分代码改动、评审建议和发布操作。
- 按职责拆分文件：宿主连接、浏览状态、文件操作和展示各自维护；共享逻辑放在真实调用方共用的位置。
- 保持现有行为和用户本机配置，记录有意改变的行为与兼容方式。

## 文件与模块

- 人工维护的单个文本文件最多 500 行，空行和注释计入；达到上限前按职责拆分。
- 保持正常格式化，通过提取完整职责满足上限，不合并语句、删除必要说明或压缩 JSX 凑行数。
- `package-lock.json`、依赖目录、`dist/` 和 `release/` 是生成内容，由相应工具维护，不手工拆分。
- `release/` 随 Git 仓库分发供 marketplace 直接安装；修改运行代码、启动脚本或包内文档后重新构建、打包并提交对应产物。打包生成便携 `.mcp.json`，保留根目录的用户开发配置。
- `npm run check` 包含行数检查；新增文件同样受检查，生成文件例外只在检查脚本中集中声明。
- 保持模块的调用接口简洁；不为拆文件引入通用框架、重复状态或循环依赖。

## 前端

- 复用 `src/ui/components/ui/` 的 shadcn Base Nova 组件及 Tailwind tokens；宿主通信集中在 `src/ui/bridge.ts`。
- 数据读取、取消与刷新由 `useWorkspace` 维护；写操作和对话引用由 `useFileActions` 维护；展示文件不直接执行文件系统操作。
- 改动交互时保留键盘操作、可访问名称、加载与错误反馈，以及小窗口下的可用性。
- 拖拽分栏结束后再提交宽度状态，避免更新初始化尺寸而打断拖拽。
- 若引入或修改使用 `@derbysoft/neat-design` 的 UI，先阅读 `~/.agents/skills/neat-design-rules/SKILL.md` 并遵守其中规范。

## 本机文件与 MCP

- `Workspace` 统一校验路径、大小写和符号链接；所有读写操作经过该校验。
- 保留已登记项目校验、聊天绑定和内容版本校验，错误不得转换成成功结果。
- 文件操作保留防覆盖、禁止移动到自身子目录和系统废纸篓语义；内容查看继续只读。
- 项目配置中本机可执行文件路径属于用户环境，发布配置变更需明确说明影响。

## 验证与交付

- 完成调用方、类型、文档与配置的同步修改，运行 `npm run check`；修改运行代码后构建并打包。
- 状态或文件操作重构验证真实调用路径，覆盖错误处理和数据保护；UI 改动验证实际渲染及关键交互。
- 行为验收使用仓库外的临时隔离环境；验收后清理临时页面、脚本和产物，仓库仅保留生产代码、文档及构建检查。
- 区分浏览器验收与真实 Codex 宿主验收，不把打包成功写成宿主安装成功。
- 提交使用 Conventional Commits；只纳入本次改动，说明验证范围和未验证项。
