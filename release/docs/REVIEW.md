# VisualFiles 产品交互与分发评审

评审日期：2026-11-04。功能与交互判断基于当前源码及项目截图；公开市场的限制依据下列 OpenAI 官方文档。以下优化点为待排期建议，本次结构重构保持现有产品行为。

## 本次工程改动

- 添加项目级 `AGENTS.md`，明确模块职责、文件操作约束、交互验证与交付规则。
- 将原 1869 行的前端入口拆成宿主连接、项目选择、浏览状态、文件操作、文件树、预览和内容展示；入口保留 18 行启动逻辑。
- 后端将搜索和文件版本转换独立维护，`workspace.ts` 从 616 行降至 500 行以内，路径校验与公开调用接口保持一致。
- `npm run check` 自动检查人工维护文件的 500 行上限；依赖锁文件和构建目录按生成内容管理。
- 按维护要求移除测试文件与测试命令；保留类型、行数检查及构建流程，行为验收使用临时隔离环境。

## 产品定位

建议围绕“在 Codex 中浏览本机项目、审阅变更并把上下文加入对话”收敛。文件树、只读查看、HEAD 对比和引用草稿构成完整工作流；已登记项目校验、废纸篓删除与不自动发送消息的约束适合保留。

目前更接近成熟的个人工具。面向其他用户分发时，安装可移植性、版本可识别性、真实宿主验证和文件操作可靠性应先于继续增加功能。

## 发布到 Codex 插件市场

存在两条分发路径，需要分别判断。

### 官方公开目录

官方支持提交运行本地程序的 Desktop only 插件。但当前本地 stdio MCP 的提交仅向获批合作伙伴开放，需要 OpenAI 联系人确认资格并为提交组织加入白名单。VisualFiles 属于这一类别，不能据此承诺普通账号现在就能自助上架。取得资格后，还需完成身份验证、提交安装包、审核和发布。[官方桌面插件说明](https://developers.openai.com/plugins/deploy/desktop-only)

项目已提供便携启动配置和包含产物的 GitHub 安装包。正式上架还需补齐发布者与支持信息、图标及完整介绍、隐私政策与服务条款，以及干净环境的审查步骤。现有 `author.name` 为 `Local`，没有许可证文件，需由维护者确定发布身份和开源许可。[官方提交及字段要求](https://developers.openai.com/plugins/deploy/submission)

### 自定义 GitHub marketplace

官方支持从 GitHub 仓库添加自定义 marketplace，这与进入官方公开目录是两件事。[官方打包及 marketplace 说明](https://developers.openai.com/plugins/build/plugins)

0.7.3 起，`.agents/plugins/marketplace.json` 指向的 `./release` 随 Git 仓库分发，包含服务、界面、启动脚本与便携 MCP 配置。可按 README 的两步命令添加 GitHub 市场并安装，普通用户无需构建。Node.js 22+ 与兼容的 Codex 客户端仍是前提；根目录的开发机 `.mcp.json` 不会复制到发布包。维护者更新后需同时构建、打包并提交生成产物。

## 建议实施顺序

1. 先完成本次模块化、500 行检查和行为回归，保留现有功能约定。
2. 在便携安装包基础上，完善运行版本识别并完成另一台 Mac 的完整安装验收。
3. 完成文件操作保护与主要交互的可复跑验证，再向小范围用户分发。
4. 优先改善搜索一致性、模式入口、键盘导航和错误恢复。
5. 根据使用反馈决定最近文件、跨文件定义等较大能力；具备合作伙伴资格后申请官方目录审核。
